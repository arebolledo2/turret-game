# User interface

`GameApp` in `scripts/game/game_app.gd` builds the default start screen: wordmark, chips for the chosen waves/difficulty/mode, Play, Settings, Quit and the difficulty and mode selectors. There is no controls screen. A Turrets button opens `TurretShowcase` (`scripts/ui/turret_showcase.gd`): a gallery of every stocked base turret and implemented form on a turntable (drag to spin) that fire on a loop via `TurretShowcaseFire` (barrel recoil, rotor spool, and stand-in bolts, streaks, flames, rings or beams per fire mode; not the real attacks), listed from `ShopCatalog` and `TurretEvolution`; Escape/B returns. Play receives initial focus. Keyboard arrows/Enter and controller directional input/A navigate menus; Escape or controller B returns from settings.

## Settings

Fullscreen, VSync, Reduced motion and Sound effects volume apply immediately and persist in `user://game_preferences.cfg` through `SettingsService`. Display operations are skipped in headless runs. Reduced motion removes model bobbing, recoil and hit blinking; combat warnings and effect ranges remain visible. Sound effects default to 70%; zero mutes the SFX bus. Legacy 2D debugging features remain unexposed.

## In-game presentation

`scripts/game/game_hud.gd` is a CanvasLayer presentation adapter for `ArenaWorld`. It shows three corner clusters (hull and core `VitalBar`s, wave pips with the timer, scrap), a short "WAVE n" banner while a wave is announced, and the game's message / Entrench / ground readouts bottom-left. The independent `ShopScreen` scene fills the screen with opaque navy, hides the combat HUD and suspends viewport 3D rendering while open. The Shop is one screen (see below): offers, the squad and installed items on the left, the build on the right. Sold cards retain their slots and hand focus to another offer or Prepare. Pause and end panels show a summary (wave strip with the failed wave in red, a reason chip on defeat, and waves/kills/scrap/time tiles) beside the current build; Main Menu tears down the run.

Shared UI pieces live in `scripts/ui/`: `UiPalette` (colours, one hue per stat), `ChamferStyle` (the cut-corner StyleBox), `UiIcons`/`UiIconData` (compact utility glyphs rasterised at 128 pixels), `ShopArt` (cached full-colour 384-pixel item SVGs and 512-pixel model portraits), `SegmentedBar`, `StatChip` (icon + value with no pill or border: a muted icon and ink text, both green or red only when the value changes), `StatFormat` (one decimal for every stat display; a before → after pair that would read the same keeps two), `StatTile`, `IconButton`, `OfferCard`, `SquadCard`, `TurretDetailsModal`, `AttackFamilyBadges`, `BuildPanel` and `VitalBar`. `ShopViewData` (`scripts/game/`) turns shop and build state into the structured data those controls draw; its `preview()` measures an item by synchronously adding its modifiers and simulating ownership, then restoring both, so the numbers match what a purchase does, and `turret_impacts()` compares that preview with the current build per deployed turret and for the hero. The theme font is Barlow Condensed, with Share Tech Mono (`Numeral` variation) for digits. Escape/controller Start toggles pause. End states support the restart button or R. Dev builds add an overlay panel (F1, or Back plus right-stick click on a controller) described in [dev tools](dev-tools.md); the HUD hides its pause panel while it is open.

The project uses the shared theme and a 1920×1080 reference canvas with canvas-item stretching. App screens and game panels were inspected at 1280×720. Focus is refreshed on phase changes, and controller navigation is exercised using real InputEvent dispatch in integration tests. Physical controller testing remains a human playtest step.

Native screenshots can be generated with `res://tools/capture_app.tscn`, which captures start, settings, pause, defeat, victory and return-to-menu screens. `res://tools/capture_game.tscn` provides shop, staged combat and stress captures. Both write under ignored `.test-results/`.

`res://tools/preview_shop.tscn` creates a deterministic Shop review at any window resolution and saves `.test-results/shop-WIDTHxHEIGHT.png`. The 1920×1080 reference canvas scales down to 1280×720; narrower logical canvases use two offer columns. The offers/squad/items column, the squad strip and the build panel scroll to follow controller focus. `--turrets` opens the turret details modal. Category tags and the misleading aggregate DPS tile are removed.

## Turret inspection and salvage recap

The full-screen Shop is a single screen with no tabs, kept quiet on purpose: no borders except the focus ring, one stat style everywhere (icon + value) and no help text. The header holds only SHOP, the next wave and the scrap balance; the turret growth summary is in the balance tooltip and each squad card shows its own "+N XP" for the wave. **Offers** come first: four borderless `OfferCard`s, each with its illustration beside the name, the rarity (or turret level) with unlabelled attack family badges, the effect stats (`ShopViewData.offer_chips`, prefixed by a family badge when the modifier is limited to that family), the full effect text, kept because many effects are unique, and the price. The lock is a padlock icon in the card's corner (gold when locked) that the mouse clicks and X / L toggles on the focused card; it is not a focus stop. The focused card shows an "A Buy" prompt. Reroll sits on the section's row. **Squad** is a strip of `SquadCard`s, one per deployed turret by stable ID: portrait, name, family badges, level, XP bar and its main numbers, with a tooltip of the full before/after numbers. While an offer is focused, `ShopViewData.turret_impacts` tints each affected card green (helped), red (hurt) or amber (mixed), draws a bar along its bottom edge and lists the change (arrow, then icon + value) under its stats; cards the offer leaves alone dim. Rule-based effects (entrenchment, proximity, conditions) count as helped without a number. **Items** lists installed upgrades as illustrated tiles with stack counts; focusing one shows its name and text in the build panel. The right-hand build panel (a fill, no outline) shows the hero (`HeroPanel`: level and XP, with XP and growth multipliers in its tooltip), then hull, core, move speed, pickup and luck and the hero weapon's damage, shots/s and reach as aligned icon / label / value rows; a value the focused offer changes reads "old → new" with the new value green or red. One line says what the focused offer does ("Helps 4 turrets · helps your hero"), and Prepare is a solid teal button at the bottom. Selecting a squad card opens `TurretDetailsModal`, which hosts the `TurretInspector`: the roster with six illustrated cards per page, the selected illustration, six stat tiles, the XP meter, the evolution milestone track and the two-press SELL; expanded stats are on the illustration tooltip. B, Escape, CLOSE or a click on the backdrop closes it and returns focus to that squad card. Controller paths run offers (Up reaches Reroll) → squad → items → Prepare; every row's right end leads to Prepare, the first card's left to Reroll (when affordable), and Prepare climbs back up. Available evolutions appear as concise buttons that open the visual evolution preview.

Before Shop, a short wave-end sequence shows collected salvage flying toward assigned turrets, filling XP bars and celebrating level gains with damage comparisons. The recap lists level-ups first (largest gains first), followed by XP-only turrets, including zero-XP recipients. Compact cards retain XP bars and actual stat gains; the panel grows to fit the roster and scales to the screen for unusually large armies, without scrollbars. The recap waits for A/Space/Continue, which can also skip the animation without forfeiting rewards; Reduced Motion keeps the count-up but removes flights and pulses.

XP presentation uses a shared high-contrast `TurretXpBar`: compact meters in the salvage recap and larger meters in selected turret details, plus compact meters on every Turrets roster button. Current/next level labels lead; exact XP totals remain available in detailed inspection.

Attack families are coloured shape badges drawn by `UiIcons.family_badge` from `UiIconData.FAMILIES`: Projectile a blue circle, AoE an orange hexagon, Instant a violet triangle, Kinetic a pink square, each with a white glyph, so they still read in greyscale. Turrets in two families show both, always in that order. `AttackFamilyBadges` reads `TurretRegistry.get_attack_families`, the same overlapping families used for item eligibility, and labels them in the details modal; offer cards, squad cards, chips and the hero weapon show them unlabelled, with the family name as a tooltip. Stat icons follow the same proposal: attack speed is a gauge, reach a crosshair, area rings, move speed chevrons, plus knockback, pierce, chain, burn, carry, core speed, entrench and entrench cap glyphs. Item cards keep their effect descriptions without legacy category tags.

Turret offers always show their level (Lv 1 included) and arrive at a random one (Lv 1 is the most common; each level up is 0.45x as likely; the best level on offer is the wave just secured + 1, capped at Lv 12 and at the highest level the turret has built forms for). From Lv 5 they arrive in their upgrade form and from Lv 10 in a random final, and the card shows the level. Price is the level 1 price times 1 + 0.35 per level gained. The turret details modal has a two-press SELL button (shop only) that pays half the same worth, so a fresh purchase loses half and a turret that has gained three levels sells for what it cost; selling also lowers the next turret's surcharge. Constants: `SHOP_TURRET_LEVEL_DECAY`, `SHOP_TURRET_MAX_LEVEL`, `SHOP_TURRET_LEVEL_PER_WAVE_HEADROOM`, `TURRET_LEVEL_VALUE_STEP`, `TURRET_SELL_RATIO`.

Shop offers can be locked for free using the card lock button, controller X or keyboard L. Locks preserve the offer and quoted price (locked offers move to the front of their weapon or upgrade group) through rerolls and wave transitions, including turret offers. Unlocking restores current pricing. Buying consumes the lock; restarting clears stock. Reroll is disabled when every offer is locked. Unlocked stock retains normal reroll costs and pricing.

Lock controls sit outside and below each card, display LOCK / UNLOCK and participate in controller focus: Down from an offer enters its lock button; left/right moves between locks, Up returns to the offer, and Down proceeds to the next offer row or nearest enabled footer action. Footer Up returns to the nearest available lock. Horizontal navigation stays within each visual row, and purchasing advances focus to the next available offer. A activates the lock independently of purchasing.

Item offers show registry rarity through their name and border colors, plus a text label: Common white, Uncommon green, Rare blue, Epic purple, Legendary orange, Unique red. Focus retains its teal outline. Item SVG artwork contains no variant-count dots; rarity comes from ItemRegistry rather than the illustration.


Preparation offers Auto Deploy (Y / F), off by default and saved between launches. Enabling it arranges immediately; subsequent preparation phases arrange again. It never starts combat and manual adjustments remain available. One turret guards each spawn zone from its centre when unrestricted, or outside its boundary when spawn placement is restricted, then remaining turrets spread along the convoy route or around the stationary core/map centre. All placements respect terrain, edges, core clearance and turret spacing. Moving resets entrenchment.

The optional Restrict Spawn Zone Placement user feature flag (F1 developer panel) defaults off. When enabled, deployment rejects positions within the zone radius plus turret clearance, including combat drops. Existing turrets inside newly generated zones must be moved before starting combat; Auto Deploy can clear them. Auto Deploy uses zone centres when this toggle is off, falling back to nearby valid ground if a centre is obstructed.

Auto-prepare layouts: Tight preserves compact placement; Balanced spreads attack circles with intentional overlap around the defended centre; Area Coverage packs ranges around the defended centre using exact circle tangencies and local refinement, reducing grid-sized gaps while strongly minimizing overlap. Crowded/blocked maps use a least-overlap fallback; circular ranges cannot tile the whole floor without gaps. The core has no coverage radius for this calculation. Prep R / right-stick click cycles the saved layout, rearranging immediately when Auto is enabled. Spawn-zone placements remain preferred anchors.

Offscreen pointers include ranged enemies (Needle Kite, Kiln Lobber, Prism Lens, ranged bosses) and Brood Tender summoners, in addition to crates and all bosses. Pointers use a pulsing amber/red halo and a moving arrow; Reduced Motion keeps them static.

The hero and core are fully healed for free at successful wave end and again at next-wave preparation. Healing never revives a defeated hero or core.

Salvage Continue uses a compact chamfered control with teal selected/focus states; shop offer locks are corner padlock icons. Rarity accents use muted neutral, mint, sky blue, lavender, gold and coral colours; rarity names remain visible. Zero-XP summaries use subdued text. Settings shows the actual/default or custom window dimensions even when no preset is selected.

## Floor showcase

The main menu's FLOORS button opens `FloorShowcase` (same shape as `TurretShowcase`): a list of every `WorldGeometry.FLOOR_THEMES` entry beside a turning patch of the real floor material with a turret for scale. Drag to turn it; Back / ui_cancel closes.

## Enemy showcase

The main menu's ENEMIES button opens `EnemyShowcase` (same shape as `TurretShowcase`): a list of every wave enemy followed by the bosses, beside a turning `ClockworkModels` model at in-game size and tint, with base health, speed and contact damage. Entries come from `EnemyRegistry.get_all_type_ids()`; summons (`EnemyEcology.SUMMONS`) and retired types (`EnemyShowcase.LEGACY`) are skipped. Descriptions come from `EnemyRegistry.TYPES` or `EnemyEcology.DESCRIPTIONS`, so a new enemy needs one of those. There is no discovered/locked state.
